# Piqae V1 execution ledger

This document connects implementation work to the accepted V1 plan. A task is
complete only when its implementation, tests, telemetry, and relevant release
gate are present.

## Status values

- `pending`
- `active`
- `blocked`
- `complete`
- `disabled`
- `preview`

## V1 source ledger

| ID | Outcome | Status |
|---|---|---|
| DOM-01 | Typed identifiers and canonical job state machine | complete |
| API-01 | Native `/v1` job and resource API | complete |
| API-02 | the legacy service printing compatibility API | preview |
| AGT-01 | Durable SQLite queue and event outbox | complete |
| AGT-02 | Signed enrolment, polling, leases, commands, and acknowledgements | complete |
| WIN-01 | Windows PDF and RAW executor | disabled |
| CUP-01 | CUPS PDF and RAW executor | preview |
| UI-01 | Linear-aligned original dashboard system | complete |
| SEC-01 | Tenant isolation, secret redaction, replay protection | complete |
| OPS-01 | Hosted and self-hosted deployment definitions | preview |
| REL-01 | Restart, lease, idempotency, and uncertainty tests | complete |
| PKG-01 | Signed native packaging and update metadata | disabled |
| DOC-01 | API, migration, self-host, and operations documentation | complete |

`complete` in this table means the V1 source path and automated evidence exist.
It is not a claim that a platform release is generally available. The
authoritative release tiers and the remaining physical-device gates live in
`release/support-matrix.yaml` and `release/v1-gates.yaml`.

The legacy compatibility surface intentionally covers the migration-critical
computer, printer, print-job, state, `whoami`, `ping`, and `noop` paths. Scales,
integrator subaccounts, billing, and every historical legacy-provider response quirk
are not represented as complete.

## Checkpoints

At each integration checkpoint, record the commit SHA, completed IDs, failed
gates, and explicitly disabled claims. New V1 scope is prohibited after the
native vertical slice begins.

### Source-complete checkpoint

- The control plane, agent, SDK, dashboard, compatibility layer, and
  self-hosting definitions are integrated on `main`.
- Windows remains Disabled until its service, installer, signing, update,
  restart, and physical PDF/RAW gates pass.
- CUPS and macOS remain Preview until packaging and physical-print evidence
  passes.
- Hosted manifests are present, but no public SaaS deployment is implied by
  this source checkpoint.
- A spooler accepting bytes is reported separately from verified physical
  output; uncertainty is preserved rather than converted into success.
